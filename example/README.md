# Worked Example: `top` → `counter` + `decoder`

This directory contains a tiny 3-module RTL hierarchy and the exact graph that
RTLGraph's pipeline (`parser/verilator_parser.py` → `graph/builder.py`)
produces from it. Every node/edge listed below was generated by actually
running the pipeline on the RTL in `rtl/` — nothing here is hand-written.

```
example/
├── rtl/                        the source Verilog
│   ├── top.v                   top-level module, instantiates the other two
│   ├── counter.v                4-bit up-counter with async reset + enable
│   └── decoder.v                combinational: tick = (count == 15)
├── generated/                  Verilator's AST dump (pipeline input)
│   ├── Vtop.tree.json            elaborated AST tree
│   └── Vtop.tree.meta.json       symbol table Verilator emits alongside it
└── README.md                   this file
```

## 1. The hierarchy

```
top
├── u_counter : counter        clk, rst_n, en  -->  count  (4-bit register)
└── u_decoder : decoder        count           -->  tick   (count == 15)
```

`top.v` wires `counter`'s output straight into `decoder`'s input via the
internal net `count_w`:

```verilog
module top (
    input  wire clk,
    input  wire rst_n,
    input  wire en,
    output wire tick
);
    wire [3:0] count_w;

    counter u_counter (.clk(clk), .rst_n(rst_n), .en(en), .count(count_w));
    decoder u_decoder (.count(count_w), .tick(tick));
endmodule
```

`counter.v` is a clocked, async-reset register:

```verilog
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)      count <= 4'd0;
    else if (en)     count <= count + 4'd1;
end
```

`decoder.v` is pure combinational logic reading that register:

```verilog
assign tick = (count == 4'd15);
```

## 2. How it becomes a graph

```
 rtl/*.v
    │  verilator --json-only --top-module top top.v counter.v decoder.v
    ▼
 generated/Vtop.tree.json + .meta.json      (Verilator's elaborated AST)
    │  parser.verilator_parser.parse_design()
    ▼
 models.design.Design                       (Pydantic: Module/Port/Signal/
    │                                         Register/AlwaysBlock/Assignment/
    │                                         Expression/ClockDomain/…)
    │  graph.builder.build_graph()
    ▼
 networkx.MultiDiGraph                      (what's described below)
```

Reproduce it yourself from the repo root:

```bash
verilator --json-only --top-module top example/rtl/top.v example/rtl/counter.v example/rtl/decoder.v
# outputs land in ./obj_dir/Vtop.tree.json + Vtop.tree.meta.json

PYTHONPATH=src .venv/bin/python3 -c "
from parser.verilator_parser import parse_design
from graph.builder import build_graph
design = parse_design('obj_dir/Vtop.tree.json', 'obj_dir/Vtop.tree.meta.json')
graph = build_graph(design)
print(graph.number_of_nodes(), 'nodes,', graph.number_of_edges(), 'edges')
"
```

## 3. The resulting graph — 26 nodes, 49 edges

### Nodes, grouped by type

| node_type | ids in this example |
|---|---|
| `Module` (3) | `module:top`, `module:counter`, `module:decoder` |
| `Instance` (2) | `instance:top.u_counter`, `instance:top.u_decoder` |
| `Port` (10) | `port:top.{clk,rst_n,en,tick}`, `port:counter.{clk,rst_n,en,count}`, `port:decoder.{count,tick}` |
| `Signal` (1) | `signal:top.count_w` — the internal wire connecting the two instances |
| `AlwaysBlock` (2) | `always:counter.always_0` (sequential), `always:decoder.always_5` (combinational, from the `assign`) |
| `Assignment` (3) | `assignment:counter.assign_2` (reset branch), `assignment:counter.assign_4` (count+1 branch), `assignment:decoder.assign_7` (`tick = ...`) |
| `Expression` (3) | `expression:counter.expr_1` (`4'd0`), `expression:counter.expr_3` (`count + 4'd1`), `expression:decoder.expr_6` (`count == 4'd15`) |
| `ClockDomain` (1) | `clockdomain:clk` |
| `ResetDomain` (1) | `resetdomain:rst_n:NEG` |

Note there's no `Register` node here — Verilator represents `count` as a
`Port` (it's also a module output) driven by a clocked `always` block, so it
shows up as `Port` + `WRITES`/`DEPENDS_ON` edges from the always block rather
than as a separate `Register` node. (A register that's purely internal, not
also a port, would get a `register:module.name` node instead.)

### Edges, grouped by relationship

| rel | meaning | example from this graph |
|---|---|---|
| `CONTAINS` | structural nesting (module owns port/signal/instance/always-block) | `module:top --CONTAINS--> instance:top.u_counter` |
| `INSTANCE_OF` | instance → the module it instantiates | `instance:top.u_counter --INSTANCE_OF--> module:counter` |
| `CONNECTED_TO` | parent net wired to a child instance's port | `signal:top.count_w --CONNECTED_TO--> port:decoder.count` |
| `DRIVES` | signal-level: who electrically drives whom | `port:top.clk --DRIVES--> port:counter.clk` (through the instance boundary), `assignment:decoder.assign_7 --DRIVES--> port:decoder.tick` |
| `READS` | assignment/expression reads a signal | `assignment:decoder.assign_7 --READS--> port:decoder.count` |
| `WRITES` | always-block writes a signal | `always:counter.always_0 --WRITES--> port:counter.count` |
| `CLOCKED_BY` / `RESET_BY` | always-block's clock/reset domain | `always:counter.always_0 --CLOCKED_BY--> clockdomain:clk` |
| `DEPENDS_ON` | derived signal→signal dependency (fanin/fanout shortcut) | `port:decoder.tick --DEPENDS_ON--> port:decoder.count` |

## 4. How to read this as a design question

- **"What clocks `tick`?"** — walk `port:decoder.tick` back through `DEPENDS_ON`
  to `port:decoder.count`, then `port:counter.count`'s `WRITES` edge from
  `always:counter.always_0`, then `CLOCKED_BY` → `clockdomain:clk`. So `tick`
  is combinational but ultimately tracks the `clk` domain through `counter`.
- **"What resets `count`?"** — `always:counter.always_0 --RESET_BY-->
  resetdomain:rst_n:NEG`, i.e. active-low async reset on `rst_n`.
- **"Where does `count_w` come from and go to?"** — it's the `Signal` node in
  `top` that's `DRIVES`'d by `port:counter.count` (through the instance
  boundary) and itself `DRIVES`'s `port:decoder.count`. That's the
  instance-to-instance data path made explicit as graph edges instead of
  living implicitly in Verilog port-connection syntax.
